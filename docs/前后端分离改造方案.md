# AI Station 前后端分离改造方案

## 一、为什么要做这个改造？

当前 AI Station 是一个 **Nuxt 全栈单体应用**：前端 Vue、后端 Nitro（Node.js）、ORM 用 Prisma，全部耦合在一个项目里。

改造目标：
1. **前后端分离** — 前端保留 Nuxt/Vue，后端用 Spring Boot 重写
2. **引入 Spring AI** — 将项目升级为 AI Agent 项目，利用 Spring AI 的 Agent 框架
3. **更强的 AI 能力** — 从目前简单的"AI 扩写"升级为真正的 Agent（对话式操作、自动分类、语义搜索等）

## 四、Agent 能力规划

改造后的核心差异在于：**从"工具调 AI API"升级为"AI Agent 驱动的工作站"**。

### 4.1 对话式操作 Agent
用自然语言操作系统，取代逐个点击按钮：
- "帮我在 Inbox 里记一条：XXX"
- "把这个 Inbox 条目转成 Issue 放到 XX 项目里"
- "我的高优先级 Issue 有哪些？"
- "把 Issue XXX 的状态改为 Done"

技术实现：Spring AI 的 **ChatClient + Tool Calling**。Agent 拥有一组 Tools（InboxTool、IssueTool、ProjectTool、KnowledgeTool），LLM 根据用户意图自动选择调用。

### 4.2 PRD 扩写 Agent（升级版）
现有的 `/api/ai/expand` 只是简单的提示词 → LLM 生成。升级为 Agent 工作流后：
- 自动搜索知识库中的相关文档作为上下文
- 生成 PRD 后自动拆解为子 Issue
- 支持多轮对话修改

### 4.3 Inbox 智能分类
TODO.md 中规划的能力：
- 新 Inbox 条目自动打标签
- 建议归属哪个 Project
- 提取关键信息

### 4.4 知识库语义搜索（后续阶段）
- 需要向量数据库支持（pgvector / 独立向量库）
- 文档入库时自动生成 embedding
- 搜索时语义匹配而非关键词匹配

## 五、实施步骤

### Phase 1：Spring Boot 项目搭建 + 数据层
1. 在 `axis/` 下创建 `axis-backend/` 子目录（Monorepo 结构）
2. 初始化 Spring Boot 4.0 + Gradle 项目
3. 创建 JPA Entity（映射到现有 PostgreSQL 表）
4. 创建 Repository 接口
5. 配置 CORS 允许前端跨域访问
6. 验证数据库连接和 Entity 映射正确

### Phase 2：CRUD API 1:1 迁移
1. 逐个迁移所有 Nitro API handler 为 Spring MVC Controller
2. 保持 API 路径兼容（`/api/inbox`、`/api/projects` 等）
3. 迁移文件上传功能
4. 添加健康检查端点
5. 验证所有 CRUD 功能与原有行为一致

### Phase 3：Spring AI Agent 集成
1. 配置 Spring AI ChatClient（OpenAI-compatible）
2. 开发 Agent Tools（调用 Service 层操作数据）
3. 添加对话记忆 Advisor
4. 创建 AgentController（SSE 流式对话 API）
5. 升级 PRD 扩写为 Agent 工作流

### Phase 4：前端适配
1. `nuxt.config.ts` 添加开发代理（proxy 到 localhost:8080）
2. 新增 Agent 对话 UI 组件（嵌入侧边栏或 CommandPalette）
3. 移除 Nitro 服务端配置
4. 验证前后端联调

### Phase 5：清理
1. 删除 `server/` 目录（Nitro API handler）
2. 删除 `prisma/` 目录和 Prisma 相关依赖
3. 适配 Electron（去掉 Nitro 启动逻辑）
4. 更新 README 和 CLAUDE.md
