# LLM 工程：Prompt 契约、可证伪评测与三层降级链

> LLM 给你的是概率不是契约：同样 prompt，今天完美大纲，明天节点超标、缺一节、API 抖动报错。对 LLM 的工程目标三件事：**输出可测量、故障有边界、服务可降级**。

---

## 1. Prompt 即接口契约

Prompt 的措辞就是 LLM 的「接口定义」——改一个词，下游所有依赖该输出的代码（解析器、评测、UI）面对的分布都变了，性质等同改 API 字段。项目宪章因此专门规定：**Prompt 与工具定义视同接口契约，修改至少按 M 级走确认**。

落地纪律：

- prompt 集中为常量（`KnowledgePrompts`/`KnowledgeQaPrompts`），不散落业务代码
- **输出结构即消费契约**：总结固定三节（TL;DR ≤3 句/要点 3–7 条/洞察 1–3 条），脑图固定纯标题层级（H1 唯一、≤4 层、5–40 节点）——下游校验器与 markmap 渲染按契约写
- 每次修改留痕：两轮 prompt 迭代均记入 design.md 变更记录，**每条注明是哪条实测失败驱动的**
- Tool 的 `@Tool` 描述同理：重构时逐字不动（模型看到的世界没变），改描述是有意的契约变更，写进 spec

## 2. 评测设施：灵魂是「可证伪」

宪章硬性条款：**AI 功能验收必须可评测，禁止只写「回答准确/效果好」**。每个设计点都回答一个问题——**这个断言真的能失败吗？**

### Golden 集

10 篇真实文章（6 中 4 英，1k–25k 字符），全文自包含 jsonl，可复现、不依赖运行时联网。

### 两级判定分工（关键设计）

- **纯脚本判定**（零 LLM、确定性）：结构检查（句数/条数）+ 脑图合法性（非标题行/围栏残留/H1 唯一居首/层级/节点数）。**能机械验证的绝不用 LLM**
- **LLM-as-judge**（只用于机械验证不了的忠实度/相关性）：judge 本身也是契约——judge prompt 与解析规则逐字留档（`evals/*-judge.md`），解析失败**记 0 分（fail-closed，宁可误杀不可放过）**

### 可证伪的连环设计

- 产物为空 → 三节全缺 → FAIL；**生成失败计入失败，不是跳过**（en-04 脑图 API 抖动计 FAIL 后 9/10 贴线达标，未被粉饰）
- QA 评测全行共享一个真实 ChatMemory 实例——conversationId 接线错导致上下文互串会被 judge 真实判 FAIL（隔离性是真测的）
- `Assumptions.assumeTrue(AI_API_KEY)` 门控：无 key 自动跳过（CI 不死）；`KNOWLEDGE_EVAL_LIMIT=N` 子集旋钮控成本

### 评测驱动的 prompt 迭代闭环

```
第 1 轮：脑图 6/9（长文节点 55/60 超标、超短文零标题）
  → 改 PROMPT_MINDMAP 强化节点数约束（留痕）
第 2 轮：结构 9/10（en-02 缺「关键洞察」节）
  → 改 PROMPT_SUMMARY 补「三节缺一不可」（留痕）
第 3 轮全量：结构 100% / 相关性 100% / 脑图 90%，全部达标
```

**没有评测，prompt 调优是玄学；有了评测，每次改动都有数字撑腰。** 已知局限如实记录：judge 与被测同模型（自评偏倚），改进方向独立 judge 模型。

## 3. 三层降级链：AI 挂了，功能还活着

LLM 及其周边（embedding/pgvector）全是外部不确定因素。原则：**降级优先于可用性**——任何一环挂了，摄取和阅读必须活着。

```
第 1 层 启动探测：查 pg_extension 无 vector 扩展
       → 直接装配关键词检索 + WARN 记原因
第 2 层 装配兜底：扩展在但 DDL 失败（权限）
       → try/catch 置 store=null，落回关键词 + WARN
第 3 层 运行时降级：embedding 调用失败（key 失效/配额尽）
       → catch 后当次检索走关键词 + WARN，不外抛
```

同哲学的另两处：产物生成失败 → FAILED 状态落库（失败是数据），摄取永远成功；LLM 单次调用 60s 硬超时，按失败处理不吊死线程。对比「没有降级的写法」：启动裸 `new PgVectorStore` 扩展不在直接起不来、检索异常直接 500——三层降级成本只是几个 try/catch + 一个接口双实现。

## 4. 幻觉控制三件套（source-grounded 问答）

1. **prompt 约束**：注入标题+总结+原文（截断标注），「只依据所给内容回答，超出明说原文未提及」
2. **不挂 Tool**：问答纯只读，模型无操作业务数据的能力——能力最小化就是安全最大化
3. **评测钉死**：golden 集含 ≥1 条超纲问题（原文未提的主题），期望拒答且**计入通过率**

诚实边界：prompt 约束是概率性的，评测是把概率维持在阈值上的机制，不是 100% 保证。

## 5. 面试问答速记

**Q：AI 功能的质量怎么保证？**
A：评测驱动。Golden 集自包含；判定分两级——机械验证用纯脚本，其余用 LLM-judge 且 judge 也是契约（fail-closed）；断言全部可证伪，失败计入不跳过；prompt 迭代由实测失败驱动并留痕。

**Q：LLM/外部服务故障系统怎么办？**
A：降级优先于可用性——三层降级链 + 失败落库为状态。核心论点：AI 是增强不是命脉，AI 死了摄取和阅读必须活着。

**Q：怎么控制幻觉？**
A：source-grounded prompt + 能力最小化（不挂 Tool）+ 超纲拒答样例计入评测通过率。

**Q：长文档怎么处理？**
A：截断 + 产物标注（已知限制明说）；演进方向 map-reduce——能讲清「现在为什么不做」。
